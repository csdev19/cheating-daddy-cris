# Briefings

One line per briefing: who it's for, and what it answers.

- [`pitch.md`](pitch.md) — a person deciding whether to try this — "what
  problem does this solve for me, and why this instead of a cheat sheet or a
  generic AI copilot?"
- [`ai-briefing.md`](ai-briefing.md) — another AI, pasted whole — "what is
  this app, what's its public interface, and what do I keep getting wrong
  about it?"
- [`stack.md`](stack.md) — a developer evaluating the codebase — "what's it
  built on, and why that and not the obvious alternative?"
- [`roadmap.md`](roadmap.md) — "what's the state of this thing right now" —
  what shipped, what's in flight, and what's honestly not decided yet.
- [`design-brief.md`](design-brief.md) — an AI doing design or UI-copy work,
  pasted whole — the palette, type, spacing and voice rules, sourced from
  `src/index.html`.

Not created: `business-brief` — this is a personal project, not a venture,
so there's no founder-sourced business model to document.

This set answers "what is this project" from the outside. It doesn't
replace `documentation/` — the sequential `01-current-state.md` through
`10-execution-plan.md` narrative there is the record of *how* the current
design was reasoned into existence (including the decisions that were
reversed along the way) and the hand-over spec for a possible future
rebuild. Read this set first to get oriented; read `documentation/` when you
need the reasoning behind a specific decision.
